## npm scripts

npm 允许在 `package.json` 的 `scripts` 字段定义脚本命令，通过 `npm run <name>` 执行。运行不带参数的 `npm run` 可列出所有脚本。其优势在于：项目脚本集中管理、不同项目有统一对外接口（如 `npm run test`）、可利用 npm 提供的钩子和环境变量。

**执行原理：** 每次 `npm run` 会新建一个 Shell 执行命令。npm 会将当前目录的 `node_modules/.bin` 加入 `PATH`（执行后恢复），因此本地安装的命令行工具可直接用名字调用。类 Unix 系统用 `/bin/sh`，Windows 用 `cmd.exe`，跨平台脚本需注意兼容性（如用 `cross-env` 设环境变量）。退出码非 0 即视为失败。即使在子目录运行，脚本也始终在项目根目录执行，可用 `INIT_CWD` 变量获取实际运行目录。

**通配符与传参：** 可直接用 Shell 通配符（`*.js`、`**/*.js`），若要传给原始命令需转义星号。向脚本传参用 `--` 分隔，如 `npm run lint -- --reporter checkstyle`。

**执行顺序：** `&` 并行执行，`&&` 串行执行（前一个成功才继续）。复杂编排可用 `npm-run-all` 等模块。

**默认值与钩子：** npm 对 `start`（默认 `node server.js`）和 `install`（默认 `node-gyp rebuild`）提供默认值。每个脚本都有 `pre` / `post` 钩子，执行 `npm run build` 实际顺序为 `prebuild → build → postbuild`。内置钩子包括 publish/install/uninstall/version/test/stop/start/restart 等，自定义脚本也可加前缀，但双重前缀（如 `prepretest`）无效。通过 `npm_lifecycle_event` 变量可判断当前阶段。

**简写形式：** `npm start`、`npm stop`、`npm test` 分别是 `npm run start/stop/test` 的简写。`npm restart` 是复合命令，会依次执行 stop、restart、start 三个脚本及其钩子（共 9 个阶段）。

**环境变量：** 用 `npm run env` 可查看全部。package.json 所有字段通过 `npm_package_` 前缀暴露（对象和数组会展开，如 `npm_package_repository_type`、`npm_package_files_0`）；npm 配置项通过 `npm_config_` 前缀获取。`config` 对象中的字段可被 `npm config set` 覆盖。Node 脚本用 `process.env` 取值，Shell 脚本用 `$变量名`。

**调试技巧：** `npm run build --verbose` 查看详细日志；用 `>` / `>>` 重定向输出到文件；依赖异常时删除 `node_modules` 重装；`npm list` / `npm outdated` 排查版本兼容性。

**最佳实践：** 用 pre/post 关联命令；脚本保持短小，复杂逻辑抽离到 Shell 或用 `npm-run-all`；区分 `build:dev` / `build:prod` 环境；避免硬编码，通过环境变量传参；控制依赖数量。

**CI/CD 集成：** npm scripts 可直接在 CI 配置中调用，例如 Travis CI 中 `script: - npm run lint - npm run test`，CircleCI 中用 `run: npm run test` 步骤。

## gulp

gulp 是基于流（Stream）的自动化构建工具，通过配置一系列 task 规范前端开发流程，不含模块化功能，擅长文件压缩合并、雪碧图、版本控制等。2014-2016 年取代 grunt 成为主流，SPA 时代后 webpack 取而代之，gulp 转战幕后，在组件库（antd、element-ui、vant）和工程流程管理中仍广泛使用。

**核心 API：** `src()` 读取文件生成流、`pipe()` 串联处理步骤（核心）、`dest()` 输出到目标路径、`series()` 串行执行任务、`parallel()` 并行执行、`watch()` 监听文件变化、`on()` 事件监听。

**任务定义：** 脚本写在 `gulpfile.js` 中。每个任务是异步函数，通过调用 callback 或返回 stream/promise 来结束。从 gulpfile 导出的是公开任务（可 `npx gulp <name>` 调用），未导出的是私有任务（仅内部组合使用）。导出 `default` 时直接 `npx gulp` 即执行默认任务。

**任务组合示例：** `series(foo1, foo2, foo3)` 按顺序执行（总耗时为各任务之和），`parallel(foo1, foo2, foo3)` 同时启动（总耗时为最慢任务的时间）。

**文件流处理：** `src()` 接受 glob 匹配文件，通过 `pipe()` 串联插件处理，最后 `dest()` 写入。gulp 有 4000+ 插件，自定义转换插件用 `through2` 开发。典型流程：读取文件 → 合并（gulp-concat）→ 过滤/转换 → 输出。

**gulp vs webpack 定位差异：** gulp 强调前端开发流程规范，是基于流的构建工具（不含模块化），通过配置 task 和执行顺序来构建流程，入口可以是任意文件，适合多页面应用和组件库；webpack 是模块化打包工具，所有资源视为模块，通过 loader 和 plugin 处理并按需加载，通常以 JS 为入口，适合 SPA。早期 webpack 曾以 `gulp-webpack` 插件作为 gulp 的子任务执行。

## npm scripts 和 gulp 对比

| 对比维度 | npm scripts | gulp |
|----------|-------------|------|
| 本质 | npm 内置脚本管理，本质是 Shell 命令封装 | 独立的基于流的自动化构建工具 |
| 配置方式 | package.json 的 scripts 字段，纯字符串 | gulpfile.js，用 JS 代码编写 |
| 编程能力 | 弱，依赖 Shell 语法和外部命令 | 强，完整 JS 编程能力 |
| 流式处理 | 不支持，需借助外部工具 | 原生支持，src().pipe().dest() 是核心 |
| 任务编排 | 靠 Shell 的 & / && 或 npm-run-all | 内置 series() / parallel() |
| 文件监听 | 需借助 watch 等外部包 | 内置 watch() |
| 插件生态 | 无插件概念，靠 npm 包组合 | 4000+ 专用插件 |
| 学习成本 | 极低，会命令行即可 | 中等，需理解流和 task |
| 跨平台 | 受 Shell 差异影响（需 cross-env） | JS 代码层面跨平台 |
| 适用场景 | 简单脚本编排、调用其他工具 | 复杂文件处理流水线、组件库发布 |

**总结：** npm scripts 是"命令的入口和编排器"，gulp 是"文件流处理的工厂"。实际项目中二者常配合使用——用 npm scripts 作为统一入口（`npm run build`），内部调用 gulp 或 webpack 完成实际构建。

## 模块化打包工具

### webpack

webpack 是静态模块打包器，将各种资源（JS、CSS、图片等）转译、组合、拼接生成可部署资源，核心完成**内容转换 + 资源合并**。

**核心流程三阶段：**
1. **初始化**：读取配置合并默认值 → 创建 Compiler 对象 → 注入内置插件、注册模块工厂 → 执行 `compiler.run()` → 根据 entry 确定入口
2. **构建**：根据入口创建 module → 调用 loader 转译为标准 JS 并生成 AST → 递归解析依赖模块 → 得到依赖关系图
3. **生成**：seal 阶段按依赖关系组装成 Chunk → emitAssets 写入文件系统

**核心概念：** Entry（编译入口）、Compiler（编译管理器，全程存活）、Compilation（单次编译管理器，watch 模式下每次变更新建）、Loader（模块转换器，处理非 JS 资源）、Plugin（基于事件钩子扩展功能）、Chunk（多个模块的组合，最终输出为文件）。

**功能集（5.0+）：** 模块打包、代码分割、按需加载、HMR、Tree-shaking、sourcemap、Module Federation、devServer、DLL、多进程等。源码规模庞大（498 份 JS、73548 行代码、162 个内置插件、237 个 hook），学习成本高。

### rollup

rollup 是 JavaScript 模块打包器，将小块代码编译成大块代码（library 或应用）。特色是原生 ES6 模块和 Tree-shaking。开发应用优先选 webpack，但打包类库时 rollup 更合适——功能更少、API 更简单、输出更干净。

**支持的输出格式：** `amd`（AMD 标准）、`cjs`（CommonJS/Node）、`es`/`esm`（ES 模块）、`iife`（立即执行函数，浏览器直接引入）、`umd`（同时支持 amd/cjs/iife）。

**基础使用：** 配置 `rollup.config.js`（指定 input 和 output），运行 `rollup -c` 打包。

**外部依赖处理：** rollup 默认不处理 npm 包，有两种方式——用 `@rollup/plugin-node-resolve` 将第三方库合并进 bundle，或配置 `external` 声明外部类库不打包（适合 library，让使用者自行安装）。

**常用插件：** `@rollup/plugin-commonjs`（支持 CJS 模块）、`@rollup/plugin-typescript`（TS 支持并导出声明文件）、`rollup-plugin-scss`（样式处理）。React、Vue、Three.js 等知名库的源码都用 rollup 打包。

### parcel

Parcel 是极速零配置的 Web 应用打包器，核心理念是让开发者专注写代码。

**核心特性：** 零配置（自动处理依赖解析、JS 转换、CSS/SCSS/LESS、图片字体、HMR）；自动安装未安装的依赖；内置热模块替换；支持动态 `import()` 代码拆分。

**基本使用：** `parcel index.html` 启动开发服务器（默认端口 1234），`parcel build index.html` 构建生产版本。入口可以直接是 HTML 文件。

**高级配置：** 支持 `.babelrc`、`postcss.config.js` 配置。构建选项包括 `--out-dir`（输出目录）、`--public-url`（资源基础 URL）、`--no-minify`、`--port`（指定端口）、`--no-cache`（清缓存）。

### snowpack（bundleless 代表）

snowpack 基于浏览器原生 ESM import，代表 bundleless（无打包）模式。传统 webpack 需把所有模块打包成 bundle，而 snowpack 让浏览器直接加载各个文件。

**ESM 带来的改变：** `node_modules` 不参与构建（效率提升至少 10 倍）；修改单文件只需单文件编译（O(1) 复杂度，reload 速度与项目大小无关）；浏览器原生按需加载，访问时再编译。开发模式启动仅需 50ms 级。

**工作原理：** `snowpack dev` 按需编译文件，源码中的 `import React from "react"` 被转换为 `import React from "/web_modules/react.js"`。`web_modules` 是对 `node_modules` 构建的结果，只需构建一次即可变为浏览器可直接加载的静态资源。

**配置扩展：** 通过 `snowpack.config.json` 配置 `build:*`（按后缀编译文件）、`run:*`（执行一次如 lint/tsc）、`mount:*`（部署目录到 URL）。可结合 webpack 做生产构建，内置支持 TS、JSX、CSS Modules。

> 补充：snowpack 已停止维护，其理念由 Vite 继承并发扬。Vite 开发模式基于 ESM（与 snowpack 思路一致），生产构建用 Rollup，已成为现代前端构建主流。

## 打包工具对比

| 对比维度 | webpack | rollup | parcel | Vite（bundleless） |
|----------|---------|--------|--------|-------------------|
| 定位 | 通用模块打包器 | 类库打包器 | 零配置应用打包器 | 基于 ESM 的下一代构建工具 |
| 配置成本 | 高（loader/plugin 复杂） | 低（简洁 API） | 零配置 | 低（开箱即用） |
| 启动速度 | 慢（全量打包） | 中等 | 快 | 极快（按需编译） |
| HMR | 支持 | 需插件 | 内置 | 内置，极快 |
| 代码分割 | 强 | 支持 | 支持 | 支持 |
| 输出格式 | 主要为 bundle | amd/cjs/esm/iife/umd | bundle | 开发时单文件，生产用 Rollup |
| 生态成熟度 | 极高 | 中等（类库领域主流） | 中等 | 快速增长 |
| 最佳场景 | 复杂 SPA、企业级项目 | JS 类库/组件库 | 快速原型、中小型项目 | 现代前端项目 |

**类型选择：**
- 做 JS 库/组件库 → **rollup**（输出干净、Tree-shaking 好、多格式）
- 复杂企业级 SPA → **webpack**（生态最全、功能最强）
- 快速原型/小项目 → **parcel**（零配置、上手快）
- 新项目/追求开发体验 → **Vite**（开发极快，生产用 Rollup）
