# JS document\.write\(\) 笔记

## 一、基础

### 1\. 方法定义

`document.write()` 是 JavaScript 原生提供的 DOM 输出方法，作用是**向 HTML 文档流中写入文本、HTML 标签、JS 代码等内容**，是最早、最基础的页面内容输出方式。

归属对象：`document`（文档对象），属于 BOM/DOM 基础 API。

### 2\. 基础语法

```javascript
// 语法
document.write(content);

// 参数：content 必选，字符串类型
// 可以是普通文本、HTML标签、变量、表达式拼接

```

### 3\. 基础使用案例

```javascript
// 1. 输出普通文本
document.write("Hello JS");

// 2. 输出HTML标签（会被浏览器解析渲染）
document.write("<h3>我是标题</h3>");
document.write("<p style='color:red'>红色段落</p>");

// 3. 拼接变量和表达式
let name = "前端开发者";
document.write("用户名：" + name);
document.write("1+1的结果：" + (1+1));

// 4. 连续写入（内容会拼接，不自动换行）
document.write("第一行");
document.write("第二行");
// 手动换行：添加 <br>
document.write("第一行<br/>第二行");

```

### 4\. 基础特性

- **解析特性**：写入的字符串中包含合法 HTML 标签时，浏览器会自动解析渲染，不会原样输出文本；

- **执行顺序**：代码从上到下执行，写在哪里，内容就输出在哪个位置；

- **参数规则**：仅接收字符串参数，非字符串会自动隐式转换（数字、布尔值等）；

- **无返回值**：方法执行后返回 `undefined`。

---

## 二、核心原理

### 1\. 核心机制：HTML 文档流

浏览器渲染页面的核心流程：

1. 浏览器解析 HTML 文档，自上而下生成 DOM 树；

2. 解析过程中形成**动态文档流**，持续向页面输出内容；

3. 页面解析完毕，**文档流关闭**。

`document.write()` 的行为完全依赖文档流状态，分两种场景：

#### 场景1：页面解析中（文档流未关闭）

JS 代码嵌入在 HTML 解析流程中（无延迟、无异步），此时调用 `document.write()`，会**直接将内容写入当前文档流**，追加到页面对应位置，不会覆盖原有内容。

正常使用的核心场景

```html
<body>
  <p>原有内容</p>
  <script>
    // 文档流未关闭，追加内容
    document.write("新增内容，不会覆盖");
  </script>
  <p>后续内容</p>
</body>

```

#### 场景2：页面解析完成后（文档流已关闭）

页面加载完成后（定时器、点击事件、DOMContentLoaded 之后），文档流已经关闭。此时调用 `document.write()`，会触发**文档流重开机制**：

1. 清空当前整个页面的所有 DOM 内容；

2. 重新开启新的空白文档流；

3. 将写入的内容渲染到空白页面中。

经典错误：**覆盖整个页面**

```html
<body>
  <p>原有页面内容，会被清空</p>
  <script>
    // 页面加载完成后执行
    setTimeout(() => {
      document.write("页面被覆盖，只剩这段内容");
    }, 1000);
  </script>
</body>

```

### 2\. 底层执行原理

- `document.write()` 属于**同步阻塞 API**，执行时会阻塞 HTML 解析、CSS 渲染、JS 执行；

- 它是**直接操作文档流**，而非操作 DOM 树，这是和 `innerHTML` 最大的底层区别；

- 写入内容后，浏览器会**立即解析渲染**，无需手动刷新 DOM，性能极低（逐行渲染）。

### 3\. 使用要点

#### 坑点1：异步执行必定覆盖页面

所有异步场景（定时器、事件监听、AJAX 回调、Promise），页面均已加载完成，文档流关闭，执行 `document.write()` 直接清空页面。

#### 坑点2：写入 script 标签的特殊问题

通过 `document.write()` 写入的 `<script>` 标签，**内部代码可以执行，但无法获取当前页面最新 DOM**，且存在执行顺序混乱问题。

同时，写入的脚本会阻塞页面渲染，风险极高。

#### 坑点3：无法在 Vue/React 框架中使用

框架基于虚拟 DOM 渲染，页面初始化后文档流早已关闭，使用会直接清空页面，破坏框架 DOM 结构，**工程化项目禁止使用**。

#### 坑点4：多次写入无换行，布局错乱

连续调用 `document.write()` 内容会无缝拼接，不会自动换行，必须手动添加 `<br>` 或块状标签，极易造成布局问题。

### 4\. 与 innerHTML / textContent 核心对比

日常开发中，`document.write()` 几乎被淘汰，对比现代 DOM 操作方法，差异如下：

|特性|document\.write\(\)|innerHTML|textContent|
|---|---|---|---|
|操作对象|全局文档流|指定DOM节点|指定DOM节点|
|是否覆盖页面|文档流关闭后全局覆盖|仅覆盖当前节点内容|仅覆盖当前节点文本|
|解析HTML标签|支持解析|支持解析|纯文本，不解析标签|
|性能|极低（阻塞渲染）|较高|最高|
|安全性|低（易XSS）|低（易XSS）|高（防XSS）|
|适用场景|老旧页面、测试打印|静态DOM渲染|纯文本修改|

### 5\. 真实适用场景

现代开发**不推荐常规使用**，仅保留2个合法场景：

1. **前端基础调试**：快速打印内容到页面，替代 console\.log，直观查看页面渲染效果；

2. **老旧静态页面兼容**：维护远古无框架、无DOM操作的静态HTML页面；

3. **动态加载静态脚本**：极少数场景下动态写入外联脚本（现已被 `createElement` 替代）。

### 6\. 现代替代方案

彻底抛弃 `document.write()`，使用标准 DOM 操作：

```javascript
// 1. 创建节点
const p = document.createElement("p");
p.innerText = "安全的文本内容";
p.style.color = "blue";

// 2. 追加到页面（不会覆盖原有内容）
document.body.appendChild(p);

// 3. 纯文本修改（安全防XSS）
box.textContent = "文本内容";

// 4. 简单HTML渲染
box.innerHTML = "<span>内容</span>";

```
